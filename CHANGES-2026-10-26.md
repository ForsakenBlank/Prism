# Spootify changes — 2026-10-26 (export / import / listening-time merge)

Port these to the Linux version. Everything below lives in `app.v2.js` and `index.html`
(the Android copy is the same files under `www/`). No changes to `main.js`, `preload.js`,
`themes.js`, `dj.js` or `style.css` were needed; the existing `.settings-choice-row.stacked
.segmented` grid already wraps the extra size buttons.

---

## 1. Export dialog (`#export-overlay` in index.html)

### Size options
- The "Split into files of up to" segmented control (`#export-size`) now has:
  `50`, `100`, `150`, `250`, **`400`**, **`450`** MB and `0` = **"No split"** (was "One file").
- The row is wrapped in `<div id="export-size-row">` so it can be hidden.

### "What to export" switches
Five `settings-toggle-row` checkboxes, in this order:

| id                 | label                                   | pref key   |
|--------------------|-----------------------------------------|------------|
| `export-songs`     | Songs, playlists and liked songs        | `songs`    |
| `export-covers`    | Covers and pictures                     | `covers`   |
| `export-stats`     | Listening time, history and ratings     | `stats`    |
| `export-settings`  | Settings                                | `settings` |
| `export-themes`    | Custom themes                           | `themes`   |

- `EXPORT_PICKS = ["songs","covers","stats","settings","themes"]`.
- Prefs persist in localStorage `spootify-export`
  (defaults `{ size: 150, songs: true, covers: true, stats: true, settings: true, themes: true }`).
- `exportOpts()` reads the five switches into `{songs, covers, stats, settings, themes}`.
- `exportContents(opts)` → array of what the data file will hold, from
  `["library","stats","settings","themes"]` (`library` ⇔ `songs`).
- In `refreshExportSummary()`:
  - `covers` is disabled when `songs` is off; `#export-size-row` is hidden when `songs` is off.
  - If nothing is picked: status "Pick at least one thing to export." and Export is disabled.
  - Songs off: "1 small file · listening time for N songs, saved to …".
  - Songs on: "N songs · about X → 1 data file + M media files, saved to …"
    (+ warning when "No split" and > 400 MB).
- Lead text: "Pick what to save. Everything except the audio and covers goes in one small
  data file; songs and covers go in separate media files."

## 2. Export file format (version 5)

An export is now **one data file + 0…N media files**, all sharing an `exportId`.
Both kinds start with the same one-line header (so `readExportHeader()` still works: it
checks that the file starts with `{"spootify":"spootify-library"` and parses line 1).

### Data file
Name depends on contents (`dataFileName(opts, stamp)`, stamp = `YYYY-MM-DD`):
- only `stats` → `spootify-listening-<stamp>.json`
- no songs and no stats (settings and/or themes only) → `spootify-settings-<stamp>.json`
- otherwise → `spootify-data-<stamp>.json`

Layout (each section on its own line; the whole file is valid JSON):
```
{"spootify":"spootify-library","version":5,"kind":"data","exportId":"…","parts":N,"contents":["library","stats","settings","themes"],"exportedAt":"…",
"library":{ playlists, currentPlaylist, queue, liked },        ← only if songs
"stats":{ "listenTimes":[…], "clock":{ since, g[168] } },       ← only if stats
"settings":{ "storage":{ key: string }, "themeImages":{ id: dataURL } }   ← if settings or themes
}
```
- `parts` = number of media files (0 when songs are off or the library has no media).
- `contents` lists what's inside; Import uses it to decide which prompts to show.

### Media files
Name: `spootify-media-<stamp>.json`, or `spootify-media-<stamp>-partNN-ofNN.json` when split.
```
{"spootify":"spootify-library","version":5,"kind":"media","exportId":"…","part":p,"parts":N,"exportedAt":"…",
"assets":{
"a1":{"type":"audio","data":"data:…"}
,"a2":{"type":"image","data":"data:…"}
}}
```
- `splitParts(plan, limitBytes)` (signature changed: no more `libraryLine` arg) returns `[]`
  when there are no assets; otherwise groups assets so each file stays under the limit
  (`limitBytes = 0` → one file). Size per asset is `assetLineLength(a)` (base64 size + wrapper).
- Media are still streamed a few MB at a time through `exportWriter(sink, handle)`.

### `library` section
Same shape as before **except**: songs no longer carry `stats`, and the library no longer
has `listenLog` / `clock`. Songs keep `rating` (when the stats switch is on). Assets are
referenced as `{ "assetRef": "a12" }`; liked songs are `[[ref, likedAt], …]`.

### `stats` section — `exportListenTimes()`
Listening time keyed **by title + artist**, not by device media ids, so it can be merged
on any device. One entry per `listenStats` key that has plays, seconds or skips,
including songs that were removed from the library:
```json
{ "title": "…", "artist": "…", "plays": 12, "seconds": 2710, "skips": 1, "lastSkipped": 0,
  "firstPlayed": 1730000000000, "lastPlayed": 1730000000000, "rating": 4,
  "log": { "2026-10": { "26": [secondsThatDay, playsThatDay] } } }
```
- Title/artist come from the live song if it's still in the library, else the stats snapshot.
- `log` is that song's slice of the day-by-day history (`spootify-log-YYYY-MM` keys).
- `clock` = the weekday × hour heatmap (`spootify-clock`), `g` rounded.

### `settings` section — `collectSettings(opts)`
- `storage`: every localStorage key starting with `spootify-` **except**
  - `spootify-log-*` (history; travels in `stats`)
  - `NOT_EXPORTED_KEYS()`: listen stats, ratings, clock, now-playing, problems, activity,
    dup-ignore, song-of-the-day, YouTube import list, `spootify-current-playlist`,
    `spootify-covers-shrunk-v1`, `spootify-dj-cues`, `spootify-dj-bpm`
    (all keyed by this device's media ids or pure bookkeeping).
  - `spootify-custom-themes` is included only when the **themes** switch is on; every other
    key only when the **settings** switch is on.
- `themeImages`: for each custom theme with `image.id`, the picture from the theme image
  IndexedDB (`spootify-theme-images`) as a data URL (via `Themes.getImageUrl` → fetch → blob).

### End of export
- Success with media: "Saved 1 data file and N media files to … Keep them together: Import
  needs the data file and every media file (pick them all at once)."
- Success without media: "Saved to …. Import it on its own: listening time is added onto
  songs with the same title and artist." (second sentence only when stats were exported).

## 3. Import (`importSplitExport(files)`)

Pick one or more files at once. Detection is unchanged (`readExportHeader`); old
single-file exports (format ≤ 3) still go through the old path.

1. Find the data file: header `kind === "data"`, or (version 4) the file with no `kind`
   and `part === 1`. Missing → "Data file is missing" message.
2. Files sharing its `exportId` are read data file first, then media parts in order.
3. `contents` (missing in older files → treated as `["library","settings"]`):
   - **has library** → check for missing media parts ("N of M media files missing … Import
     anyway?"), then the existing Merge / Replace choice (`showImportChoice`).
   - **no library** → one confirm: "Import this file? It has your listening time, settings
     and custom themes. Listening time is added onto yours: songs with the same title and
     artist are merged, and songs you don't have show up as removed in Stats (tap one to
     rename and merge it). The app restarts afterwards."
4. Lines are streamed (`fileLines`): `"library":`, `"stats":`, `"settings":` lines are
   parsed; asset lines are stored as blobs only if the library needs them (`neededRefs`).
   Lines `}`, `}}`, `"assets":{` and the header are skipped.
5. `applyImportedLibrary(lib, mode, …)` if there is a library (unchanged, plus it still
   understands v4 song `stats`, `listenLog` and a library-level `clock` for older files).
6. **After** the library (so its songs exist to match), `mergeListenTimes(stats)`.
7. Toast: "Library imported · Listening time added · X matched, Y as removed songs".
8. Settings: if the file also had a library, ask "Restore settings and themes?"; if not, the
   step-3 confirm already covered it. Then `restoreSettings(settings)` and `location.reload()`.

### `restoreSettings(s)`
- Writes every `storage` key back (skipping non-`spootify-` keys, logs, `NOT_EXPORTED_KEYS`,
  and `spootify-custom-themes`).
- Theme pictures: each `themeImages` entry → `Themes.putImage(blob)` → new id; themes
  pointing at a picture that didn't come across get `image = null`.
- Custom themes are **added** to the device's own (`Themes.loadCustom()`), a theme with the
  same `id` replaced; saved with `Themes.saveCustom`.

## 4. Merging listening time by name

New helpers (placed just before `fixDuplicateGroup`):

- `songNameKey(title, artist)` → `NFKC`, lowercase, collapse whitespace, trim;
  `title + "\n" + (artist || "unknown artist")`.
- `statsNameIndex(exceptKey?)` → `Map(nameKey → stats key)`: songs in the library first
  (`statsKeyFor(song)` = `mediaId` or `"id:" + id`), then removed songs' snapshots in
  `listenStats` (entries with a `title`).
- `mergeListenTimes(data)` → `{ matched, added }`:
  - For each `listenTimes` entry, find the key by name. No match → new key
    `"name:" + nameKey` (shows in Stats as a removed song; re-importing hits the same key).
  - **Adds** plays, seconds, skips; `firstPlayed` = min, `lastPlayed` / `lastSkipped` = max;
    sets the rating only if the target has none; adds each `log` day into
    `spootify-log-YYYY-MM` (`[seconds, plays]` summed) and marks the month dirty.
  - Adds the `clock` grid cell by cell, `since` = earliest.
  - Saves stats, log, clock; `refreshStatsUi()`.
  - Note: importing the same file twice counts it twice (it's additive by design).
- Anything iterating `listenStats` that needs a real song already goes through
  `findSongByStatsKey(key)`, so the `name:` keys are safe.

## 5. Renaming a removed song in Stats to merge it

- In `renderStatsSongRows` and `renderStatsSkippedRows`, rows whose song is no longer in the
  library ("removed") are now clickable; the subtitle reads "… · removed · tap to rename",
  tooltip "Rename (or merge into another song)".
- `renameRemovedStats(key)`:
  1. Prompt for the title, then the artist (`showPrompt` with `input`, maxLength 200).
  2. `statsNameIndex(key).get(songNameKey(title, artist))`:
     - **no match** → just rename the snapshot (`title`, `artist`), toast "Renamed".
     - **match** → confirm "Merge listening time? "<name>" already has X plays (time). Add this
       song's Y plays (time) and history onto it?" then `moveMediaRecords(key, target)` (the
       existing helper used by duplicate merging: moves/sums stats, likes, rating and every
       day of history), fix the merged entry's title/artist/art from the target, save stats,
       log and library, toast `Merged into "<name>"`.
- Use case: two copies of a song where one title was misspelt by a character — rename the
  removed one to the correct spelling and their times combine.

## 6. Listening clock

- The weekday × hour heatmap (`spootify-clock`) is now exported (in `stats.clock`) and merged
  on import (summed; `since` = earliest). For v4/v5-early files the same thing happens from
  `library.clock` inside `applyImportedLibrary` (replace mode overwrites instead of adding).

## 7. Wi-Fi sync between devices (new file `sync.js`)

Home → **Sync** (`#sync-open-btn`, next to Export) opens `#sync-overlay`. Two devices on the
same network swap only what changed since they last synced *each other*, and the user
ticks every change in both directions.

### Roles and transport
- **Host = the desktop (Electron) app.** `main.js` has a "WI-FI SYNC (host)" section: an
  `http` server on port **47823** (`0.0.0.0`), started/stopped by IPC `sync:host` (on/off,
  returns `{ code, port, addresses }` with the LAN IPv4 addresses from `os.networkInterfaces()`).
  - Every request is `POST /sync` with a JSON body `{ code, action, … }`; CORS `*`, `OPTIONS` → 204,
    body limit 32 MB.
  - The **6-digit code** (`crypto.randomInt`) is checked in main; 10 wrong codes → 429 until hosting
    is toggled off/on.
  - Valid requests go to the page with `webContents.send('sync:request', id, body)`; the page answers
    with `ipcRenderer.send('sync:reply', id, answer)`; 5-minute timeout per request.
  - `preload.js` exposes `electronAPI.sync = { host(on), onRequest(cb), reply(id, answer) }`.
  - On Linux the same code works; the firewall must allow incoming TCP 47823 on the LAN.
- **Client = the phone (or another desktop).** In the dialog: PC address + code → Connect.
  - Android: requests go through a new Java plugin method `BackgroundAudio.httpPost({ url, body, timeout })
    → { status, text }` (HttpURLConnection on a background thread), because the WebView won't
    fetch plain http from another machine. `AndroidManifest.xml` got
    `android:usesCleartextTraffic="true"`. **Needs an APK rebuild.**
  - Desktop/browser client: plain `fetch` with `Content-Type: text/plain` (no CORS preflight).
- Last address is remembered in localStorage `spootify-sync-addr`; each install has a random
  `spootify-device-id`. Both keys were added to `NOT_EXPORTED_KEYS()` so exports never copy them.

### Actions (the `action` field)
| action          | request                         | answer |
|-----------------|---------------------------------|--------|
| `hello`         | `{ name }`                      | `{ deviceId, name }` |
| `offer`         | `{ peerId, name }`              | the host's offer (below), built against its sync point for `peerId` |
| `media`         | `{ id, offset, length }`        | `{ size, type, length, data(base64) }` — a slice of a stored blob (audio or cover) |
| `upload-start`  | `{ type }`                      | `{ token }` |
| `upload-chunk`  | `{ token, data(base64) }`       | `{ ok }` |
| `upload-end`    | `{ token }`                     | `{ id }` = new media id on the host (`storeBlob`) |
| `apply`         | `{ peerId, name, items }`       | `{ ok }` — host applies the items, saves its sync point, reloads itself 1.5 s later if settings/themes changed |

Media move in **1.5 MB** chunks (`SYNC_CHUNK = 3 * 512 * 1024`, a multiple of 3 so the base64 pieces join).

### Sync points ("since the last sync")
IndexedDB database `spootify-sync`, store `baselines`, key = the other device's id.
`saveSyncPoint(peerId)` records, right after a sync:
`{ at, day: "YYYY-MM-DD", entries: ["<playlist>\u0001<nameKey>"], ids: { songId: [title, artist] },
liked: [nameKey], ratings: { nameKey: 1-5 }, stats: { statsKey: [plays, seconds, skips] },
log: { statsKey: [seconds, plays] } (today only), clock: g[168] }`.

### The offer — `buildSyncOffer(peerId)`
- `songs`: every library entry `{ p (playlist), id, title, artist, duration, loudness, src, timestamp, m (mediaId), c (artId) }`.
- `removed`: sync-point entries no longer in the library (deliberately removed → never re-offered).
- `liked` (nameKeys), `ratings` ({ nameKey: r }): the current state, so the other side can drop no-ops.
- `changes` since the sync point (or everything, the first time):
  - `likes` `[{title, artist, liked}]`, `ratings` `[{title, artist, rating(0 = cleared)}]`,
  - `renames` `[{from:{title,artist}, to:{title,artist}}]` (same song id, different name),
  - `listen` = `listenSince(point)`: per song, current totals minus the sync point's (clamped ≥ 0),
    with its day-by-day `log` for days after the sync day plus today minus today's recorded part;
    `clock` = grid minus the sync point's grid. **This is what makes "10 h then 10 more minutes"
    send only the 10 minutes.**
- `settings`: `collectSettings` keys minus `SYNC_LOCAL_KEYS` (UI state like settings tab, sidebar,
  export prefs, milestones, custom themes…). `themes` + `themeImages` (data URLs).
- `firstSync`: true when there was no sync point.

### Turning two offers into tickable items — `syncItems(from, to)`
Categories in display order: Renamed songs, New songs, Listening time, Likes, Ratings,
Settings, Custom themes. Each item `{ cat, label, sub, data, checked }`.
- **Renames** only if `to` has the old name and not the new one; renamed names are excluded from New songs.
- **New songs**: `(playlist, name)` not on `to`, not in `to.removed`. If `to` has the same name in
  another playlist, the sub says "no download" (audio is reused).
- **Listening time**: every `listen` entry (+time, +plays), plus one "Time-of-day chart" item for the clock.
  Songs `to` doesn't have will show there as removed (merged by name via `mergeListenTimes`).
- **Likes / ratings**: only when the song exists on `to` (or is being added/renamed) and the value differs.
- **Settings**: keys whose values differ; **unticked by default**; sub shows short values
  "125 (now 100)". **Themes**: missing or different (ignoring the picture id).
- A setting or theme that differs appears in both directions; they're paired so ticking one
  unticks the other (`it.pair`).

### Applying — `applySyncItems(items)` (both sides use it)
Order: renames (all library songs with the old name, and their stats snapshot) → new songs
(into the playlist with that name, created if needed; audio = transferred `localM/localC`, else
a local song with the same name lends its media; skipped if it had audio and none arrived) →
likes → ratings → listening time (`mergeListenTimes`) → settings (localStorage) → themes
(`restoreSettings` with just the themes). Returns `{ reload }` when settings/themes changed.

### Client flow (`connectAndCompare` → review → `runSync`)
1. `hello`, then `offer` from the host; build our own offer against our sync point for the host.
2. `incoming = syncItems(theirs, mine)`, `outgoing = syncItems(mine, theirs)`; render
   (`renderSyncReview`, `syncCategory`: a checkbox per category with "n of m", Show/Hide for the
   item list, a checkbox per item). First sync shows a note that listening time is everyone's full
   total (untick if already merged through an export).
3. Sync: download media for ticked incoming songs we don't have by name (`pullMedia`), upload media
   for ticked outgoing songs the host doesn't have by name (`pushMedia`), `apply` on the host,
   `applySyncItems(incoming)` locally, `saveSyncPoint(host id)`, reload if needed.
4. Nothing to swap → "Already in sync." and Done still records the sync point on both sides.
- Unticked changes are skipped for good (they're inside the new sync point), except new songs,
  which keep being offered until the other side has them or removed them.

### UI bits
- `#sync-host` (desktop only): switch "Let a phone connect to this PC" → shows address(es), the code
  in large digits and a live status line (`#sync-host-status`: connected / comparing / receiving /
  "Synced with Phone · N changes received"). Closing the dialog stops hosting.
- `#sync-connect`: address + 6-digit code inputs (Enter = Connect).
- `sync-overlay` is in `OVERLAY_IDS` and Back closes it (ignored while transferring).
- CSS: `.sync-*` rules after `#export-progress-fill` in style.css.

### Verified (two desktop windows with separate storage, A hosting, B on 127.0.0.1)
- Wrong code rejected. First sync: new songs both ways, like and rating across, "song  one / ART"
  matched "Song One / Art", listening time summed (3600 s + 300 s → 3900 s on both).
- A listened 10 more minutes → second sync offered only "+10m, +2 plays" for that song → both 4500 s.
- Third sync: "Already in sync." Rename on A, rating + speed setting on B → all applied; paired
  setting toggles behave.

## Quick test checklist
1. Export with everything on, 50 MB split → one `spootify-data-…` + several `spootify-media-…partNN-ofNN`.
2. Import all of them (Merge) on a fresh profile → songs, covers, liked, ratings, stats,
   history chart, clock, settings and themes (after the restart prompt) all come back.
3. Export with only "Listening time" → `spootify-listening-…json`, small.
4. Import it on a device with the same songs → plays/time add up; songs it doesn't have
   appear as "removed" in Stats.
5. Tap a removed song, rename it to exactly match a song you have → merge prompt → times combine.
6. Old exports (single file, or v4 split parts) still import.
